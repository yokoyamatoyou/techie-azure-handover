## Findings Mapped To Notecode

### 1. Redundancy Removal vs `body_length_floor_chars`

External writing sources repeatedly value concision. The Gist is the strongest compression-oriented source, and Web-writing sources also reward concise, scannable text.

Mapping:

- Keep redundancy handling out of DraftWriter until `draft_writer_depth_budget_contract_smoke_failure_diagnosis` finishes.
- Do not add a "shorten" instruction to any prompt template.
- If adopted later, express redundancy as local issue types: `duplicated_claim`, `empty_summary_sentence`, `decorative_detail_burden`.
- A redundancy fix must be length-neutral or length-preserving when `body_length_floor_chars` is active, unless the article is already above final floor with buffer.

Safe contract language candidate:

```text
Remove only repeated or decorative text that does not carry a claim, transition, scene, or reader function. Do not compress source-backed depth when a body floor is active.
```

### 2.論証強化 vs Source-Grounding

Technical writing sources value clear causal links, precise claims, and handling likely reader objections. LLM reliability sources warn that fluent outputs can introduce unsupported information even when grounded context is supplied.

Mapping:

- Logical continuity must narrow, qualify, or reorder existing confirmed claims; it must not add new causal facts.
- QA candidates should detect "certainty exceeds support" rather than instructing the writer to invent missing support.
- Targeted rewriter should change assertion strength locally: `X causes Y` -> `source範囲ではXがYに関係する説明として扱われている` only when that relationship exists in confirmed claims.

Safe contract language candidate:

```text
If a logical bridge is needed, use only confirmed claims, assigned claim IDs, selected excerpts, or a weaker supported relationship. Do not create a new cause, result, comparison, or benefit.
```

### 3. 技術文書の硬さ vs note/Hatena Blog Naturalness

The Gist, Google, Microsoft, GOV.UK, and JTF sources are valuable for clarity, but they are not all blog-style sources. Current notecode targets natural Japanese blog articles for note/Hatena while preserving genre-specific formality.

Mapping:

- `announcement` may adopt more formal public-document clarity.
- `market_explanation` and `comparison_guide` may adopt more paragraph-role and argument-continuity checks.
- `company_service_intro`, `case_study`, and `daily_activity` need softer application.
- Do not adopt one-sentence-one-line, footnotes, strict definition bolding, or technical-book paragraph templates globally.

Safe contract language candidate:

```text
Apply technical-writing strictness only to claim support, actor clarity, and logical scope. Preserve note/Hatena paragraph rhythm and genre warmth.
```

### 4. Long Norms Into Brief/Profile/QA, Not Prompt Text

Current `CONFIG_AND_PERSONA_POLICY.md` requires compact prompt templates and separation of config, persona, prompt, and code. External sources should not become prompt bodies.

Mapping:

- Article brief can carry short style contract flags, not manuals.
- Style/profile can carry compact rule IDs, not full prose.
- QA can emit issue types with minimal fix instructions.
- Long explanations stay in proposal docs only.

Candidate compact fields, if a future owner approves schema/config work:

```json
{
  "style_conflict_contract": {
    "redundancy_mode": "floor_safe_local_only",
    "argument_scope": "source_claims_only",
    "technical_strictness": "genre_weighted",
    "rewrite_scope": "flagged_spans_only"
  }
}
```

### 5. Deterministic QA vs LLM Editor Judgment

Some style issues are surface-detectable; some require semantic judgment. Current docs prefer deterministic QA where possible and do not allow a broad LLM review loop.

Mapping:

- Deterministic candidates: repeated connectors, ending buckets, sentence/paragraph rhythm, first-person variants, heading length/specificity heuristics, model-frequent terms, duplicate headings, body floor, obvious sentence fragments, unsupported-certainty markers when no supporting claim type exists.
- LLM/editor judgment candidates: oversimplified causality, paragraph role drift, term drift, rhetorical overstatement, reader burden from unnecessary detail.
- Hybrid approach: deterministic QA emits candidates; LLM targeted rewriter only edits flagged spans when current rewrite contract allows it.

### 5.5. Stylometry Signals vs AI-Detector Overreach

Japanese quantitative-stylistics and LLM-output studies support using sentence length, POS composition, phrase patterns, function-word patterns, endings, and punctuation placement as signals. They do not justify treating stylometry as a binary "human vs AI" publication gate.

Mapping:

- Keep stylometry as issue-candidate evidence for `JapaneseQualityChecker`, not as an automatic rejection threshold.
- Do not create an "AI detector" acceptance rule.
- Use deeper signals such as phrase/POS pattern repetition only when they point to a concrete rewriteable problem: broken predicate, sentence rhythm monotony, nominalization overuse, connector stack, or repeated phrase template.
- If a signal cannot produce a span-local, fact-preserving fix instruction, keep it report-only.

Safe contract language candidate:

```text
Use Japanese stylometry as deterministic evidence for concrete quality issues, not as a binary AI-written label. Every rewrite-triggering signal must map to a local, fact-preserving fix.
```

Use genre strength instead of global rules.

| `announcement` | explicit dates/actors/targets, plain public-document clarity, short structure | heading clarity, punctuation consistency | long blog-like expansion, dramatic rhetoric |
| `case_study` | attribution of customer voice, outcome support, causality qualification | paragraph role handoff, term stability | unsupported emotional/result claims |

### 7. Watchlist Duplication And Banned-Word Bloat

Current docs already have risky phrases and model-frequent words. External lists should not create a second independent watchlist.

Mapping:

- Merge only after a deterministic audit proves an uncaught recurring failure.
- Prefer phrase family issue types over long banned strings.
- Keep context: risk words are not absolute bans.

Candidate issue-family names:

- `empty_importance_preface`
- `unsupported_superlative_or_intensity`
- `generic_transition_stack`
- `decorative_summary_sentence`

### 8. Targeted Rewriter Locality

External logic and style norms can easily push a whole-article rewrite. Current targeted rewriter must preserve facts, claim IDs, section purpose, speaker, and non-target paragraphs.

Mapping:

- A QA issue must carry span or section-local scope.
- Rewriter must not receive full external style manuals.
- Rewriter must not fix unflagged paragraphs.
- Rewriter must not add new claims to improve logic.

Minimum future acceptance checks:

- changed span count is bounded,
- non-target paragraphs remain byte-identical or meaning-identical,
- numbers/dates/names unchanged,
- first person unchanged,
- claim IDs unchanged,
- final body floor not worse when floor is active.

## Do-Not-Adopt Findings

Do not adopt these as Route B / 0506 rules:

- Gist全文 or Web資料全文 as prompt text.
- One sentence per line as a general article format.
- Footnotes / technical-book column conventions for normal blog output.
- Universal bolding of first definitions.
- Universal paragraph-initial connector requirements.
- "Shorter is always better" or fixed-percentage content reduction.
- Hard banned-word deletion.
- Strict technical-writing tone for all genres.
- Broad prompt tuning to "sound better".
- LLM-as-judge loops as a replacement for deterministic QA.
- AI-detector-style pass/fail decisions based on stylometry alone.
- New repair loop or fallback route.
- Any source expansion that adds unsupported effects, outcomes, third-party feelings, numbers, comparisons, or strong causality.

## Deterministic QA Candidates

Strong deterministic candidates:

- `sentence_fragment_or_broken_predicate`
  - Detect Japanese sentences ending in particles or copula fragments such as `は。`, `で。`, `を。`, after excluding headings and lists.
  - Directly relevant to the current smoke manual finding.

- `heading_specificity_mismatch_candidate`
  - Heuristic: heading uses broad promise words while assigned claim count/source thickness is low.
  - Candidate only; final decision may need semantic review.

- `certainty_without_support_marker`
  - Detect strong certainty markers (`必ず`, `すべて`, `唯一`, `No.1`, `確実に`, etc.) when no supporting claim category permits that strength.
  - Must not become a global ban.

- `generic_transition_stack`
  - Detect repeated paragraph-initial connectors and transition-only sentences.
  - Already overlaps current connector/stylometry policy; audit before adding.

- `decorative_summary_sentence`
  - Detect summary-only closers with no source term, claim noun, or reader action.
  - Useful only if it does not shorten floor-active articles below buffer.

- `term_drift_candidate`
  - Deterministic part: repeated key concepts with multiple labels in headings/body.
  - Semantic confirmation may be needed before rewrite.

- `punctuation_spacing_or_symbol_mismatch`
  - JTF/public-doc supported notation consistency; low-risk if kept formatting-only.

- `pos_phrase_pattern_monotony_candidate`
  - Detect repeated phrase/POS templates only as a concrete monotony or broken-sentence signal.
  - Must not become a binary AI-written detector or a publication gate.

Weak / semantic QA candidates:

- `oversimplified_causality`
- `paragraph_role_drift`
- `reader_burden_detail`
- `rhetorical_overstatement`

These should first be report-only or editor-review candidates, not automatic rewrite triggers.

## Genre Applicability Notes

`announcement`:

- Strong: public-document clarity, explicit dates/targets/actors, concise structure.
- Guard: no unnecessary warmth, no blog expansion.
- Floor risk: announcement may legitimately be shorter; do not force blog depth.

`case_study`:

- Strong: customer voice attribution, outcome support, causality strength.
- Guard: do not invent customer feelings or results.
- Floor risk: source-near sequence can add depth, but not unsupported outcomes.

`comparison_guide`:

- Strong: fair comparison, supported selection criteria, term stability.
- Guard: no ranking or competitor claims without source.
- Floor risk: expand by explaining supported axes, not generic SEO advice.

`daily_activity`:

- Strong: natural scene rhythm, source-near detail, no invented feelings/outcomes.
- Guard: technical-writing strictness low; diary naturalness matters.
- Floor risk: thin source should not be padded to 1400 with generic reflection.
