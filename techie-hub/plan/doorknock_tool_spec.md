# コトムスビ 仕様書（v1.0 実装済み）

> **ステータス: 実装完了 (2026-02-07)**
> 実装ファイル: `C:\tetie\doorknock\`

## 1. コンセプト

**「代理店が商談の場で、URLを入れるだけで"刺さる"診断レポートを30秒で生成できるツール」**

### コトミガキとの違い

| 項目 | コトミガキ（既存） | コトムスビ（新規） |
|:--|:--|:--|
| 対象ユーザー | 自社スタッフ / 詳細分析者 | 代理店（士業・制作会社） |
| 入力項目 | URL, 競合URL, 業種, プラットフォーム, URLタイプ, バランス | **URLのみ**（業種は自動判定） |
| 出力の粒度 | 8タブ＋詳細スコア＋深掘り分析 | **3セクション（Fear/Loss/Hope）** |
| 目的 | 改善施策の立案 | **商談のきっかけ作り（ドアノック）** |
| トーン | 技術的・中立 | **危機感→機会損失→希望** の営業トーン |

---

## 2. 画面フロー（3ステップ）

```
[STEP 1: 入力]  →  [STEP 2: 分析中]  →  [STEP 3: 結果表示 + PDF]
```

### STEP 1: 入力画面
- **URL入力欄**（1つだけ。大きく中央配置）
- 「診断開始」ボタン（目立つCTA）
- 業種は `IndustryDetector` で自動判定（手動選択は不要）
- ロゴ・代理店名の表示エリア（将来：リセラーID連動）

### STEP 2: 分析中画面
- プログレスバー（3段階: URL取得 → 分析中 → レポート生成）
- 「約30秒で完了します」の表示
- 分析中のアニメーション（信頼感を演出）

### STEP 3: 結果表示画面
- **ヘッダー**: 対象URL、業種（自動判定）、診断日時
- **3セクション構成**（Fear → Loss → Hope の順）
- **PDF出力ボタン**（「診断レポートをダウンロード」）
- **再診断ボタン**（別のURLを診断）

## 3. 結果画面の3セクション設計

### セクション1: 警告（Fear）🔴
**見出し例**: 「法的リスクの検出結果」

データソース: `legal_checks`, `legal_summary`, `regulatory_check`

表示内容:
- 法的リスクの件数（重要 / 注意 / 参考）
- 最も深刻なリスク上位3件の概要
- 該当法規名（特商法、景表法、薬機法等）
- 代理店トーク例: 「このままだと〇〇法違反で課徴金のリスクがあります」

UIイメージ:
```
┌─────────────────────────────────────┐
│ ⚠ 法的リスク: 3件検出              │
│                                     │
│ 🔴 重要(1件) 🟡 注意(2件)          │
│                                     │
│ ■ 特定商取引法                      │
│   返品条件の記載が確認できません     │
│ ■ 景品表示法                        │
│   「No.1」表記の根拠が不明です      │
│ ■ ステマ規制                        │
│   広告表記の視認性が低い可能性       │
└─────────────────────────────────────┘
```

### セクション2: 喪失（Loss）🟡
**見出し例**: 「AI検索での機会損失」

データソース: `aio_results`, `citation_snippets`, `integrated_results`

表示内容:
- AIOスコア（100点満点のゲージ表示）
- AI検索での引用可能性（引用候補の有無）
- SEOスコアとの比較（レーダーチャートまたはバー）
- 代理店トーク例: 「競合はAIに引用されていますが、貴社は引用されていません」

UIイメージ:
```
┌─────────────────────────────────────┐
│ 📊 AI検索スコア: 42 / 100          │
│ ████████░░░░░░░░░░░░ 42%           │
│                                     │
│ SEOスコア:  58 / 100                │
│ AIOスコア:  42 / 100  ← 要改善     │
│                                     │
│ AI引用候補: 0件（引用されにくい状態）│
│                                     │
│ 💡 同業種の平均: 65点               │
└─────────────────────────────────────┘
```

### セクション3: 希望（Hope）🟢
**見出し例**: 「改善すれば、こう変わります」

データソース: `deep_recommendations`, `schema_suggestions`, `integrated_results.improvements`

表示内容:
- 改善提案の上位3件（具体的なアクション）
- 期待される効果（定量的な見込み）
- 構造化データの提案（「この設定を入れるだけで改善」）
- 代理店トーク例: 「この3つを実施すれば、15-20%の改善が見込めます」

UIイメージ:
```

│ ✅ 改善提案 TOP 3                   │
│                                     │
│ 1. メタディスクリプションの最適化    │

│                                     │
```

## 5. デザイン方針

- **カラー**: ダーク系ヘッダー + ホワイト背景（信頼感）
- **フォント**: Sora + Noto Sans JP（コトミガキと統一）
- **トーン**: 専門的だが平易。代理店が「そのまま見せられる」品質
- **レスポンシブ**: タブレット横持ちでも見やすい（商談時のiPad想定）
- **ブランディング**: 代理店ロゴ差し替え可能（将来対応）

## 6. 技術的な制約・前提

### 使用するaio2-mainのモジュール（最小セット）
- `core/scraper.py` + `core/safe_fetch.py` — URL取得
- `core/industry_detector.py` — 業種自動判定
- `core/engine/orchestrator.py` — メイン分析（`analyze_url()`）
- `core/scoring_engine.py` — スコア算出
- `core/legal_checks/` — 法務チェック
- `core/aio_analyzer.py` — AIOスコア
- `core/citation_generator.py` — 引用候補
- `PDFreport/` — PDF生成（簡易版を新規作成）

### 分析パラメータ（固定値）
- `balance`: 50（SEO/AIO均等）
- `deep_mode`: False（軽量モード）
- `platform_override`: None（自動判定）
- `url_type_selected`: "自動判定"
- `enable_question_simulation`: False

### 所要時間の目標
- 分析完了: 30秒以内
- PDF生成: 5秒以内
