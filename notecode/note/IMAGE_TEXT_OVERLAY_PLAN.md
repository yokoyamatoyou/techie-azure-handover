# 画像への文字重ね簡易編集機能：実装計画

日本語対応と、ローカルから Azure 移行を想定した設計。  
ニールセンの10原則、Hickの法則（Hick–Hyman）、Shneidermanの「8つの黄金律」に沿った実装計画とする。

---

## 1. 適用するUX原則の対応表

### 1.1 ニールセンの10のユーザビリティヒューリスティクス

| # | 原則 | 本機能での適用 |
|---|------|----------------|
| 1 | **システム状態の可視性** | 編集ダイアログで「プレビュー」を常時表示。適用中はスピナー＋「処理中」表示。完了時に「文字を重ねました」と通知。 |
| 2 | **実世界との一致** | 「文字を重ねる」「位置：上・中央・下」など、ユーザーの言葉に合わせたラベル。フォントサイズは「小・中・大」で表現。 |
| 3 | **ユーザーの制御と自由** | 元画像は残す（上書きしない）。編集結果は別ファイルで保存し、「元に戻す」＝元画像を再度表示可能にする。 |
| 4 | **一貫性と標準** | 既存UI（保存ボタン・ダイアログ・通知）と同じパターンで「文字を重ねる」ボタン・ダイアログ・適用／キャンセルを配置。 |
| 5 | **エラー防止** | 文字未入力では「適用」を無効化または警告。長文は字数制限＋プレビューで事前に確認可能にする。 |
| 6 | **認識しやすさ** | 位置は「上部中央」「中央」「下部中央」をアイコンまたは短い文言で選択。前回の設定は記憶しない（毎回デフォルトでシンプルに）。 |
| 7 | **柔軟性と効率** | 上級者向けは後拡張（キーボードショートカット等）。初版は「選択肢を少なく」で効率化。 |
| 8 | **美しくミニマルなデザイン** | ダイアログは「テキスト・位置・サイズ・色」のみ。余計なオプションは出さない。 |
| 9 | **エラーの認識・診断・回復** | フォント読み込み失敗時は「文字を重ねられませんでした」と理由を表示。保存失敗時も同様にメッセージで伝える。 |
| 10 | **ヘルプとドキュメント** | ダイアログ内に1行ヘルプ（「タイトルやキャッチコピーを画像に重ねて表示できます」）。詳細はREADME等へ。 |

### 1.2 Hickの法則（Hick–Hyman）

- **選択肢を減らす**: 位置は 3 種類（上・中央・下）、フォントサイズは 3 段階（小・中・大）、色は 2 色（白・黒）程度に限定し、意思決定の負荷を下げる。
- **段階的開示**: 初回は「文字を重ねる」のみ表示。クリック後にダイアログで詳細オプションを表示（一覧に並べない）。
- **分類**: 「表示」と「見た目」を分ける（位置＝表示、サイズ・色＝見た目）。ラベルでグループ化する。

### 1.3 Shneidermanの「8つの黄金律」

| # | ルール | 本機能での適用 |
|---|--------|----------------|
| 1 | **一貫性を保つ** | 既存の「保存」「ダイアログ」「通知」と同じ見た目・用語・操作順（入力→プレビュー→適用）。 |
| 2 | **ショートカット** | 初版では省略。将来、同じ設定で連続適用する場合に「前回と同じで適用」等を検討。 |
| 3 | **情報的フィードバック** | 適用完了時に「〇〇.jpg に文字を重ねました」のように、何が起きたかを具体的に表示。 |
| 4 | **対話の完了** | 適用でダイアログを閉じ、一覧に編集後画像が追加されることで「タスク完了」が明確になる。キャンセルで何も変わらない。 |
| 5 | **簡単なエラー処理** | バリデーションエラーはその場でメッセージ。例外時は「もう一度お試しください」＋理由を短く表示。 |
| 6 | **取り消しを容易に** | 元画像は削除しない。編集結果は別ファイル。一覧から「元の画像だけ表示」できるようにする（元画像のパスを保持）。 |
| 7 | **内部統制の支援** | ユーザーが「どの画像に・どんな文字を・どこに」を選ぶ。システムが自動で上書きしない。 |
| 8 | **短期記憶負荷を減らす** | オプションは少なく、ラベルで意味が分かるようにする。前回設定の復元は初版では行わない（選択肢を増やさない）。 |

## 2. 機能要件（日本語対応・Azure移行を踏まえた範囲）

### 2.1 スコープ

- **対象**: 生成済み画像一覧の各画像に「文字を重ねる」を実行できること。
- **入力**: テキスト（日本語・英数字対応）、位置（上部中央・中央・下部中央）、フォントサイズ（小・中・大）、文字色（白・黒）。
- **出力**: 元画像を変更せず、別ファイルとして保存し、一覧に編集後画像を追加（または編集後を表示してダウンロード可能にする）。

### 2.2 日本語対応

- **フォント**: 日本語表示可能なフォントを1つ用意する。
  - **ローカル**: `assets/fonts/` 等に配置（例: Noto Sans JP Regular、IPAex ゴシック等の再配布可能なフォント）。
  - **Azure**: デプロイパッケージに同梱するか、環境変数 `TEXT_OVERLAY_FONT_PATH` でパスを指定できるようにする。
- **エンコーディング**: 入力テキストは UTF-8。PIL/Pillow の `ImageDraw.text()` に渡す前に、フォントで描画可能な形で渡す。
- **文字数制限**: 表示崩れ防止のため、1行あたりの文字数または総文字数に上限を設ける（例: 総 50 文字、超過時は警告）。

### 2.3 Azure 移行を想定した設計

| 観点 | 方針 |
|------|------|
| **ファイル保存先** | 画像保存ディレクトリ（生成画像・編集後画像）を設定で切り替え可能にする。ローカルは `Path`、Azure は Blob Storage の URL またはマウントパスを想定。 |
| **パスの抽象化** | 「画像を保存する」「画像を読み込む」をモジュール（例: `note/image_storage.py`）に集約し、`storage.save_image(bytes, key)` / `storage.get_image_path(key)` のようなインターフェースで扱う。初版はローカル実装のみ。 |
| **フォントパス** | 環境変数または `config.json` の `images.text_overlay_font_path` で指定。未設定時は `assets/fonts` のデフォルトフォントを使用。Azure App Service ではアプリに同梱したパスを指定。 |
| **一時ファイル** | 編集処理はメモリまたは一時ディレクトリで完結させ、本保存はストレージ抽象経由にする。Azure では一時ディレクトリが揮発性のため、保存先を必ずストレージ側にすること。 |
| **状態** | セッション内の `state.generated_images` は「表示用のパスまたは URL のリスト」に統一。Azure では Blob の URL を並べる形に拡張可能にする。 |

## 3. 技術構成

### 3.1 モジュール分割

```
note/
  image_storage.py      # 新規: 保存・読み込みの抽象（初版はローカル実装のみ）
  image_text_overlay.py # 新規: 文字描画ロジック（PIL、フォント、位置・サイズ・色）
  note_writer_app.py    # 変更: コンテナに「文字を重ねる」追加、ダイアログとストレージ呼び出し
```

- **image_storage.py**: 現在の `llm_client` の `output_dir` や `note_writer_app` の `UPLOAD_DIR` を、設定から読む「保存ルート」＋キーで保存／取得する形に寄せるための土台。初版では既存パスをラップする薄い層でも可。
- **image_text_overlay.py**: 画像パス（またはバイト列）・テキスト・位置・サイズ・色を受け取り、描画した画像のバイト列または保存パスを返す。フォントパスは引数または設定から取得。
- **note_writer_app.py**: 「文字を重ねる」ボタン、ダイアログ（テキスト、位置、サイズ、色）、適用時の `image_text_overlay` 呼び出しと `state.generated_images` 更新、`generated_images_container.refresh()`。

### 3.2 設定拡張（config.json / 環境変数）

- `config.json` の `images` に以下を追加（任意）:
  - `text_overlay_font_path`: フォントファイルのパス（相対または絶対）。未設定時は `assets/fonts` のデフォルトを使用。
  - `generated_images_dir`: 生成画像の保存先（Azure 移行時に Blob パス等に切り替え可能にするためのキー）。
- 環境変数（Azure 向け）:
  - `TEXT_OVERLAY_FONT_PATH`: フォントの絶対パスまたはアプリ相対パス。
  - `GENERATED_IMAGES_DIR`: 生成・編集画像の保存ルート（ローカルでは `note/generated_images` 相当）。

### 3.3 データフロー（Azure を見据えた形）

```
[ユーザー] 「文字を重ねる」クリック
    → ダイアログ表示（テキスト・位置・サイズ・色）
    → プレビュー更新（同一画像にオーバーレイ表示するか、簡易プレビュー）
[ユーザー] 「適用」
    → image_text_overlay.render(source_path, text, position, size, color)
        → 画像読み込み（storage または Path）
        → フォント読み込み（config/環境変数）
        → 描画 → バイト列または一時ファイル
    → storage.save_image(result, key) または既存の output_dir に保存
    → state.generated_images に編集後画像のパス（または URL）を追加
    → generated_images_container.refresh()
```

将来 Azure Blob にする場合は、`storage.save_image` が Blob にアップロードして URL を返し、`state.generated_images` にその URL を入れる形に差し替える。

### 3.4 画面レイアウト

既存の NiceGUI 構成（カード・ダイアログ・ボタン配置）に合わせ、一覧とダイアログのレイアウトを定める。

#### 3.4.1 生成画像一覧エリア（コンテナ内）

| 要素 | レイアウト |
|------|------------|
| **親** | 既存どおり `ui.column().classes("w-full gap-3")`。各画像は「画像ブロック ＋ 操作行」の縦並び。 |
| **画像** | 既存どおり `ui.image(path).classes("w-full rounded-lg border")`。幅は親に合わせる。 |
| **操作行** | 既存の `ui.row().classes("w-full items-center justify-between")` を維持し、**左にファイル名ラベル、右にボタン2つ**を並べる。 |
| **ラベル** | 既存どおり `ui.label(path)`。長いパスは `truncate` または `min-w-0 flex-grow` で省略表示し、狭い画面でもボタンが押しつぶされないようにする。 |
| **ボタン順** | **左から「文字を重ねる」「保存」**。編集（文字重ね）→ 保存（ダウンロード）の操作順に合わせる。両方とも `props("flat dense")`、色は「文字を重ねる」を `text-emerald-700`、「保存」を既存どおり `text-emerald-700` で統一。 |
| **余白** | ボタン間は `gap-2` 程度。行全体はカード内の他要素と同様、余白を変えずに追加する。 |

既存コードでは操作行が「ラベル ＋ 保存」のみのため、「文字を重ねる」を保存の左隣に挿入する形にする。

#### 3.4.2 編集ダイアログ

既存のジャンル編集・削除確認ダイアログと同じパターン（`ui.dialog` ＋ `ui.card`）に揃える。

| 要素 | レイアウト |
|------|------------|
| **サイズ** | `ui.card().classes("p-4 w-full max-w-md")` 程度。フォーム項目が多いため、既存の `w-96` よりやや広く、最大幅で制限（モバイルでもはみ出さない）。 |
| **タイトル** | 「文字を重ねる」を `ui.label(...).classes("text-lg font-bold mb-2")` で表示。 |
| **ヘルプ** | タイトル直下に1行「タイトルやキャッチコピーを画像に重ねて表示できます。」を `text-sm text-gray-500 mb-4` で表示。 |
| **フォーム** | 上から順に: (1) テキスト入力（textarea 1行または input、プレースホルダー付き）、(2) **表示位置**（「位置」ラベル＋横並びで「上」「中央」「下」をラジオまたはセグメント）、(3) **見た目**（「サイズ」小・中・大、「色」白・黒を横並び）。グループ間は `mb-4`、ラベルは `text-sm font-medium text-gray-700 mb-1` で統一。 |
| **ボタン** | フッターに `ui.row().classes("w-full justify-end gap-2 mt-4")` で「キャンセル」「適用」。キャンセルは `props("flat")`、適用は `classes("primary-btn")` または `props("color=primary")` で主操作とする。既存の削除確認（キャンセル｜削除）と同じ並び・役割にする。 |

Hickの法則に合わせ、位置・サイズ・色はそれぞれ選択肢を少なくし、横並びで一目で選べるようにする。

#### 3.4.3 既存UIとの一貫性

- **カード** | 画像セクションは既存どおり `with ui.card().classes("w-full bg-emerald-50 p-4 rounded-lg")` 内にあり、コンテナだけ変更する。新規カードは追加しない。 |
- **ダイアログ** | `with ui.dialog() as dialog, ui.card().classes(...)` の形と、タイトル・本文・ボタン行の構成を、ジャンル編集・削除確認と同じに揃える。 |
- **通知** | 適用完了・エラー時は既存どおり `ui.notify(...)` を使用。 |

#### 3.4.4 レスポンシブ・視認性

- **狭い画面**: 操作行のラベルは `truncate` 等で省略。ボタンは「文字を重ねる」「保存」の2つのまま、折り返し時は右端で2つとも折り返すか、ラベルを短くしてボタンを常に表示する。ダイアログは `max-w-md` と `w-full` で、小さいビューポートでは幅いっぱいにする。
- **コントラスト**: ボタンは既存の emerald 系と揃え、フォームラベルは `text-gray-700` で十分なコントラストを確保する。

## 5. 非機能要件（原則との対応）

- **パフォーマンス**: 描画は同期的でよいが、タイムアウトを考慮し、大きな画像はリサイズ後に描画する等の制限をかけてもよい。
- **セキュリティ**: 保存パスは必ず「指定された保存ルート以下」にし、パストラバーサルを防ぐ。入力テキストは表示用にサニタイズ（改行・長さ制限）。
- **アクセシビリティ**: ボタンとダイアログにラベルを付け、既存の NiceGUI スタイルと揃える。

---

## 6. まとめ

- **ニールセン・Hick・Shneiderman** に沿い、選択肢を少なく（位置3・サイズ3・色2）、一貫したフィードバックと取り消し可能な操作にし、エラー時は理由を伝える設計とする。
- **日本語** は専用フォントを1つ用意し、設定でパスを切り替え可能にする。
- **Azure 移行** を見据え、保存先とフォントパスを設定・環境変数で切り替え可能にし、将来的に `image_storage` で Blob に対応できるようにする。

上記 Phase 1〜3 の順で実装すれば、原則を満たしつつ、ローカルから Azure への移行も行いやすい構成になる。
