# ゼロベース再構築 — 計画作成時に送るプロンプト

**使い方**: 参照 13 本と `zero_base_rebuild_plan_creation_prompt.md` を @ で読み込ませた**あと**に、このファイルの「送るプロンプト」をコピーして送る。  
**注意**: 計画を作成させるチャットには、このファイルを @ で読ませてもよい（プロンプト文だけなので問題ない）。**first_prompt は読ませない**。first_prompt には「別タブで…」などの手順が書いてあり、AI が勘違いするため。

---

## 送るプロンプト（コピーして送る）

```
あなたは、大規模リファクタとアーキテクチャ設計に強いシニアエンジニアです。

@ で読み込んだ「zero_base_rebuild_plan_creation_prompt.md」に記載の【背景】【制約】【参照ドキュメント】【成果物の指定】および、そこに列挙された参照ドキュメント（AGENTS.md, ALGORITHM.md, GAP_AND_NEXT_POLICY.md 等）の内容を踏まえ、**notecode（C:\tetie\notecode）の「生成部分」をゼロから再構築するための詳細な計画**を作成してください。

計画が承認されたのち、実装担当がその計画に従って (1) 対象コードの archive（依存関係は復活可能に）、(2) WORKLOG の圧縮と archive、(3) 新パイプライン・新 UI のゼロベース実装に進みます。計画には「何をいつ archive するか」「何を残すか」「新構成とフェーズ」「依存関係の復活手順」に加え、**承認後すぐに実行する archive の具体的な手順**（移動の順序・確認リスト）まで含めてください。

【出力形式】
- 計画の本文は **1 つの Markdown ファイル**にまとめる。目次をつけ、フェーズごとの見出しで飛ばし読みできるようにする。
- 計画ファイルの**冒頭または「参照・導線」セクション**に、必要な各ファイルへの導線を書く。例: 残すドキュメント・残すコードのパス、archive 先のパス、復活手順への参照。これがあれば、それ以外の不要なファイルはすべて archive してよい旨を計画に含める。
- 進捗管理用に **PROGRESS.md** の雛形を**別途**出力する。内容: フェーズ一覧、各フェーズの状態（未着手/進行中/完了）、現在のフェーズ、次のアクション、依存関係の復活手順・archive 一覧への参照。
- 不要物はすべて archive する方針と、フェーズ進行中に必要になったら archive から必要なだけ復活する手順を計画に含める。

上記に従い、(1) 計画の全文（1 ファイル想定）、(2) PROGRESS.md の雛形を出力してください。
加えて、計画本文には**承認後の archive 整理手順（手順・順序・確認リスト）を独立章として必ず含める**こと。
```
