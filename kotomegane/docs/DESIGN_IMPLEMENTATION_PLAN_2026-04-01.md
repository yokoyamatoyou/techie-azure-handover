# Kotomegane Design Implementation Plan 2026-04-01

## Purpose

`コトメガネ` を TECHIE 共通UIの最初の基準実装にする。  
次回起動時は、この文書を見て `デザイン込みで完成` まで進める。

## Product Definition

`コトメガネ` の主目的は次。

- 設定したキーワードや質問で、自社や自社製品が AI 回答に出るかを確認する
- そのとき、よく一緒に出る外部名・外部サイト・論点を把握する
- 必要時のみ競合比較を補助的に使う

競合比較は残すが、主役にはしない。

## Design Goal

- 初見で迷わない
- 質問1件からすぐ使える
- 何を入れて何を見るかが一目で分かる
- 詳細機能はあるが、最初の画面では重く見えない
- `コトメイク` `コトミガキ` に移植できる共通骨格を持つ

## Shared Design Application

`kotomegane` は TECHIE 共通デザイン原則の最初の当てはめ先とする。

共通で守るもの:

- フォントファミリー
- H1、区分見出し、項目名、本文、注記の階層
- カード形状
- 余白
- `入力 / 主結果 / 詳細運用` の骨格

`kotomegane` で差分として持ってよいもの:

- ごく薄いウォームクリーム系の背景トーン
- `AI回答で見えるか` を連想しやすい補助コピー
- 可視化サービスとしての主強調色

## Fixed Layout

### Top

- 共通H1
- 共通アイコン
- サービス名
- 一文の価値訴求

### Section 1

- `入力する`
- 主役入力だけを置く
- 通常は質問1件
- `＋` ボタンで追加
- 最大3件まで

### Section 2

- `結果を見る`
- 最初に見る結論を3つまで
- 自社が出たか
- 外部名・外部サイトは何か
- 次に確認すべき質問は何か

### Section 3

- `詳細を使う`
- 上段は `運用` と `詳細` の 2 タブで整理する
- `運用`
  - 質問セット
  - 定期バッチ
  - 一括実行
  - 実行履歴
  - export
- `詳細`
  - 意図マップ
  - 不足ページナビ
  - 比較
  - 下書き
  - 根拠URL

この層は初見ユーザーの主導線から一段下げる。

## Explicit UX Rules

### 1. Question Input

- 1件を既定表示
- `＋ 質問を追加`
- 最大3件
- 3件以上は初期段階では扱わない

### 2. Primary Result

最上段の主役指標は次に絞る。

- 自社が出たか
- 外部名や外部サイトが見えるか
- 次に見直す質問は何か

### 3. Wording

- UI で英語の内部語を出さない
- `競合` を主語にしすぎない
- `意図クラスタ` のような固い語は補助説明を付ける

### 4. Typography

- H1 は共通ブランド領域として扱う
- セクション見出しは 3 段導線を読むための主ラベルとして揃える
- 項目名、補助文、本文の階層差を明確にする
- `kotomegane` 独自の文字組みは作らず、後で他サービスへ移せる状態にする

### 5. Service Identification

- 共通骨格は維持する
- ただし `kotomegane` だと分かるよう、背景にごく薄いサービス固有トーンを使う
- 状態色とは混ぜない
- 背景差分は弱く、識別の補助として使う

### 6. Batch Position

- 手動実行が主導線
- バッチは詳細運用へ退避
- 定期バッチは残す
- prompt caching は内部前提として維持
- 初期表示では `OpenAI のみ正式対応` を明示する

## OpenAI Scope

開始時点は OpenAI のみを正式対応とする。

- 手動実行
- 定期 batch
- prompt caching
- 競合比較

将来拡張のため、取得層と可視化層は責務を分ける。

## Visual Positioning

`90ドル相当` は実価格ではなく、見た目の印象基準として使う。

狙う印象:

- 難しすぎない
- 業務で使える
- 初見でも触れる
- すぐ価値が分かる
- 安っぽく見えない
- 信頼感がある
