# 別タブからの質問への回答（送信用）

そのまま貼って返せます。

## 回答（そのまま送付可）

ありがとうございます。方針を以下で確定します。

1. **UI項目対応表は最優先で作成します。**  
   形式は `現行UI項目 / 新input_contract項目 / 扱い(残す・非表示・削除) / 理由 / 移行メモ` の1表で統一します。  
   この表が Phase1 の着手条件です。

2. **記事種類は今回で最終確定します。**  
   表示名・内部キー・媒体差分（note/はてな/SEO）を固定し、以後はこの表を single source にします。  
   例: 解説・日常・ブランド・お知らせ・事例・業界分析・比較レビュー（内部キーは英字snake_caseで固定）。

3. **旧パイプライン依存UIは、原則「完全削除」方針で進めます。**  
   ただし、運用上リスクがある画面は 1 リリースだけ「非表示」で逃がし、次リリースで削除する2段階運用にします。  
   （どの画面が例外かは UI項目対応表に明記）

4. **生成後リーガルのUI導線は「自動実行＋任意再実行」で確定します。**  
   - 生成完了直後に自動チェック  
   - 結果表示は本文結果の直下（同画面）  
   - 「再チェック」「提案反映（必要時）」を任意操作で提供

5. **互換性境界は「ログは準厳密互換」で進めます。**  
   `latest_generation_output.json` など既存連携で参照される主要キーは維持し、拡張は追加キーで行います。  
   削除・改名が必要な場合は migration note を計画に含めます。

6. **判断主体について**  
   最終判断はプロダクト側（あなた）で行います。  
   計画側は「推奨案＋根拠＋影響範囲」を提示し、あなたが Yes/No を確定する運用で進めます。

7. **人間らしいブログに必要な最小入力（UI）**  
   「誰視点で」「誰に向けて」は必須にします。  
   動的質問は常時多問にはせず、記事種類に応じて 0〜2 問だけ出す方式（軽量）を推奨します。
